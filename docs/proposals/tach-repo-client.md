## 2. Quyết định cần duyệt

| #   | Câu hỏi                                     | Khuyến nghị                                                                                                                                                                                                                                                                                                                                                                                                                                            | Phương án khác                                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1  | Client lấy `@hustalo/shared` bằng cách nào? | **Tarball trên GitHub Release của monorepo.** Repo đang public nên không cần token. Monorepo build shared ra `dist/` (JS + `.d.ts`), chạy `npm pack` khi gắn tag `shared-vX.Y.Z` rồi đính file `.tgz` vào Release. Client khai báo `"@hustalo/shared": "https://github.com/Danghoa894/HustAlo/releases/download/shared-vX.Y.Z/hustalo-shared-X.Y.Z.tgz"`; lockfile ghi lại integrity.                                                                  | (b) GitHub Packages: cần PAT kể cả khi chỉ đọc, ở cả máy dev và CI. (c) Chép mã shared vào repo client kèm script kiểm khớp: dễ lệch, trái quy tắc "hợp đồng chỉ đặt ở `packages/shared`". (d) Dùng git dependency: không được, vì npm không cài được thư mục con của repo git. |
| Q2  | Ai deploy production?                       | **Monorepo vẫn là repo phát hành duy nhất.** Repo client chỉ build và push `hustalo-client:<sha>`. Monorepo ghim phiên bản client trong file `infra/client.version` (đổi qua PR). `cicd-docker` dùng `CLIENT_IMAGE_TAG` lấy từ file đó, tách khỏi `IMAGE_TAG` của server. Job `verify` checkout repo client đúng SHA đã ghim để chạy smoke. SSH key VM chỉ nằm ở một repo, và mỗi lần deploy luôn là một cặp server–client đã kiểm tra là tương thích. | Repo client tự deploy service `client`: phải đặt secret SSH ở hai repo, và server/client có thể lệch phiên bản trên production.                                                                                                                                                 |
| Q3  | E2E của client lấy backend ở đâu?           | **Clone monorepo cạnh repo client.** Local dùng `../HustAlo`, ghi đè được bằng `HUSTALO_SERVER_DIR`. CI checkout monorepo đúng ref ghim trong `server.version` của repo client. `fixtures.ts` chỉ đổi đường dẫn; hành vi restart server và stack relay giữ nguyên.                                                                                                                                                                                     | Chạy server từ image Docker Hub: phải viết lại AC-092 và `call-network` bằng container. Image chạy `NODE_ENV=production` nên `COOKIE_SECURE` và `DEV_CALL_RING_TIMEOUT_MS` cũng phải xử lý thêm; rủi ro cao hơn.                                                                |
| Q4  | Bỏ `client/` khỏi monorepo không?           | **Bỏ**, nhưng chỉ sau khi repo client chạy xanh và đã deploy được một lần. Như vậy chỉ còn một nguồn sự thật. CI monorepo vẫn chạy E2E của client ở SHA đã ghim, để thay đổi server làm hỏng client thì bị bắt ngay.                                                                                                                                                                                                                                   | Giữ cả hai: hai bản client sẽ lệch nhau.                                                                                                                                                                                                                                        |
| Q5  | Có giữ lịch sử git của `client/` không?     | **Giữ**, bằng `git subtree split --prefix=client`: lịch sử commit chạm vào `client/` được chuyển sang repo mới.                                                                                                                                                                                                                                                                                                                                        | Copy thư mục và bắt đầu lịch sử mới.                                                                                                                                                                                                                                            |
| Q6  | `.spec/` để ở đâu?                          | **Giữ ở monorepo** làm nguồn sự thật duy nhất. CLAUDE.md của repo client trỏ tới `../HustAlo/.spec/`; muốn sửa spec thì mở PR vào monorepo. Quy ước: đường dẫn `client/…` trong spec ứng với gốc repo `HustAlo-client`, nên không phải sửa hàng trăm đường dẫn trong spec.                                                                                                                                                                             | Chép spec sang repo client: hai bản spec sẽ lệch nhau.                                                                                                                                                                                                                          |

- Tạo repo GitHub `Danghoa894/HustAlo-client` (để trống, public, giấy phép GPL-3.0 như monorepo).
- Thêm vào repo client 2 secret `DOCKERHUB_USERNAME` và `DOCKERHUB_TOKEN`. Không cần secret SSH, vì việc deploy vẫn do monorepo làm.
- Duyệt từng PR. Gắn tag `shared-v*` trong monorepo, hoặc cho phép agent gắn.
